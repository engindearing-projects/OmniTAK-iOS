# OmniTAK iOS 2.19.0 (build 26051105) — K9Blue SAR feedback closeout

Branch: `feat/closed-test-feedback-may2026`.

Closes the SAR-feedback sweep K9Blue sent on Discord (5/10/26). All five
issues #13–#17 landed as separate PRs (#19–#23), integration-tested
against iPhone 17 Pro simulator, then fast-forwarded into the
integration branch.

## What's new

### Lasso multi-select (PR #19 / issue #16)
- New `Lasso` mode in the drawing tool cluster — long-press + drag to
  draw a closed polygon, everything inside gets selected
- Pure-geometry `LassoSelectionService` (Franklin PNPOLY) + identity-only
  `SelectionContext` for downstream consumers
- Floating orange "✕ N selected" pill (no grey backplate, icons float)
- 6 RED→GREEN XCTests under `OmniTAKMobileSpecs/LassoCore`

### In-app data package authoring (PR #20 / issue #15)
- `DataPackageBuilder` — pure-Foundation selection → zip with manifest +
  CoT (markers) + KML (drawings) + GPX (tracks), `estimatedSize`
- `DataPackageZip` — minimal STORED-only ZIP writer/reader (CRC32 +
  central dir); round-trips through the same path importers use
- Modal sheet at Settings → MISSION → "Build data package…"
- Publish-to-TAK button disabled until Mission API wires up (this PR ↓)
- 3 RED→GREEN XCTests under `OmniTAKMobileSpecs/DataPackageBuilderCore`

### Marti Mission API client + Create-mission sheet (PR #21 / issue #14)
- Both OTS and TAK Server CIV speak the same Marti API on 8089 mTLS
- `MissionAPIClient` protocol + `URLSessionMissionAPIClient` impl —
  `getMissions`, `createMission`, `addContentsToMission` on real wire
  format (`PUT /Marti/api/missions/{name}`,
  `POST /Marti/sync/missionupload`, `PUT contents { hashes }`)
- Settings → MISSION → "Create new mission (BETA)" sheet wired to real
  `ServerManager.activeServer` host on 8443
- 11 RED→GREEN XCTests under `OmniTAKMobileSpecs/MissionAPIClientKit`
- **BETA** — Marti `MANIFEST/manifest.xml` emitter, member picker, and
  package attach wired to Publish all deferred to a follow-up.

### FEMA / IC symbology catalog + marker palette (PR #22 / issue #13)
- `FEMAIconCatalog` — 12 entries across 5 categories (Command,
  Medical, Aviation, Vehicles, Support). SF Symbols scaffolding (real
  FEMA artwork is a follow-up). Each entry carries `cotType` +
  `iconsetPath` for ATAK/iTAK round-trip
- `FEMAMarkerPaletteView` — modal sheet from PointDropperView
- `PointMarker` + `MarkerCoTGenerator` + `PointDropperService` updated
  with optional `femaKindRaw` (Codable migration: older saves still parse)
- 12 RED→GREEN XCTests under `OmniTAKMobileSpecs/FEMACatalogSpec`

### KML/KMZ user map overlays (PR #23 / issue #17, half)
- `UserMapOverlay` descriptor + `UserMapOverlayManager` (disk-backed CRUD)
- `KMLOverlayRenderer` — pure KML → `MKPolygon`/`MKPolyline` conversion
- Settings → MAP OVERLAYS → "User Overlays (KML/KMZ)" sheet with
  opacity slider, visibility toggle, rename, delete
- GeoPDF row shown as disabled "Coming soon" — parser deferred (Flight
  Tactics vendor evaluation, otherwise hand-roll CGPDF LGIDict reader)
- 3 RED→GREEN XCTests under `OmniTAKMobileSpecs/...`
- Naming: existing `Plugins/Core` already defines a `MapOverlayDescriptor`,
  so new types are prefixed `User*` to avoid collision

## Visual-verification gap (honest)
Simulator launched cleanly with all 5 PRs integrated and rendered the
default map view + bottom nav without crash. Deeper navigation (open
Settings → MISSION sheet, drop a FEMA marker, draw a lasso, import a
KML overlay, publish a mission) was **not** captured in sim screenshots —
`cliclick` taps continued to collide with iOS 26.2 home-screen gestures,
a recurring issue with this simulator.

This release should be considered **lightly tested** until K9Blue and
the closed-test pool exercise the new flows. Bronx County DA evaluation
should hold off on hammering the new features until on-device QA passes.
